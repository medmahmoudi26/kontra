# handler — the one Temporal Go handler for every kontra actor

One canonical Go binary, run one-per-actor. It owns the **workflow** half of a run: it serves the
Nexus operation `kontra.actor:run` and schedules each batch as a `RunBatch` activity onto the
actor's **own** task queue — regardless of whether that actor is written in Python or Go.

```
TS orchestrator ──Nexus kontra.actor:run (EntryInput → BareRef)──▶
  handler (this module, Go, one per actor identity at runtime)
    • Nexus service + Run workflow-run op   ← generated by protoc-gen-go-temporal
    • RunWorkflow: kontra.fetch_blob → RunBatch → Close → kontra.store_blob
    • blob activities kontra.store_blob / kontra.fetch_blob, on {name}-{version}
    • claim-check (codec/cas/objectstore) + identity naming
       └─Temporal, on {name}-{version}-sessions──▶ actorkit activity worker
                                                   (Python OR Go), Redis state
```

`RunBatch` and `Close` are scheduled **by name** and are *not* implemented here (ADR 0018): the
actor process is itself a Temporal activity worker and polls the sessions queue directly, and
Temporal splits workflow and activity across languages by design. One activity per batch — the
time-boxed turn loop is gone, because the actor heartbeats for itself (once per unit outcome), so
`HeartbeatTimeout` is a true liveness check and `StartToClose` is no longer a guillotine.

## Decoupled from actorkit

`handler` and `actorkit` **never import each other**. They meet only at (1) the queue name plus
the two activity names (`RunBatch` / `Close`) and (2) the JSON wire contract (`EntryInput`,
`BareRef`, the `RunBatch` payload) defined in `/contracts`. The shared naming — endpoint
`kontra-{name}-{version}`, queues `{name}-{version}` and `{name}-{version}-sessions` — is a
contract each side derives independently (`internal/identity` here; the workflow derives the
sessions queue from its own task queue, since workflow code cannot read env), congruence-tested.

## Status

Shipped. `_gen` lives here (`_gen/kontra/v1/kontrav1temporal`, service `kontra.actor`, op `run`),
and so do the workflow, the two blob activities, and the claim-check + identity plumbing that used
to sit in the Go SDK seam (now `sdk/go` + `runtime/go`). The old "port `run_batch`/`close` here too" item is closed by ADR 0018
rather than done: those two went to the actor process instead.
