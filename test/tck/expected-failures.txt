# The pinned A2A TCK's expected outcomes against the gate (a2aproject/a2a-tck d4d6fae7887f88ef607fb461c13e3b0e1802f19b;
# spec/relay.md §0, §16 tck_*; D18, DM4-12, DM4-24): the tests that do not pass, failures and skips alike.
# test/tck/kontra_xfail.py marks every expected failure of the binding being run xfail(strict=True) and fails the run
# when an expected failure passes, errors or skips, when a test that is not listed ends xfailed (the TCK xfails SHOULD
# requirements itself), when an expected skip does not skip, when a test of the binding being run skips and is not
# listed (the TCK skips whenever a prerequisite request fails, so a regression would otherwise hide as a skip), or
# when an entry names no collected test: for each variant and binding, the xfailed set and the skipped set (apart
# from the other bindings' tests, "Transport ... not configured") are exactly the entries here. Format: one pytest
# node id per line, "#", and the reason, which cites an a2a-tck issue or a decision; "skip <node id>" is an expected
# skip; a line "[<variant> ...]" starts the entries of those variants (TCK_VARIANT, scripts/tck.sh); the entries
# before the first section are every variant's. A test's binding is its id's suffix, else its directory, else its
# function's name suffix (_jsonrpc, _rest) or its class's name prefix (TestJsonRpc, TestRest). Delete an entry when
# its cause is gone (strict XPASS, or "listed as a skip, but passed", says so) and re-pin deliberately.
#
# Measured by M4 WP-02's review on 28 Oct with fresh TCK ids per test (test/tck/kontra_tck_ids.py, DM4-24), the four
# variants each run twice (jsonrpc, then http_json); see DM4-24 for the counts.
#
# Not listed, because the gate passes them: CORE-SEND-003 (a2a-tck#202 asserts success for an unsupported media type;
# the seller answers ContentTypeNotSupportedError, which the gate relays as a failed task, spec/relay.md §6.4).
